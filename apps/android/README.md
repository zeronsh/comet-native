# Zeron Android

Native Android viewport (Kotlin + Compose, minSdk 26, phone portrait). No engine on-device — joins the same workspace/chat2 rooms via edge.

## Toolchain

- JDK 17
- Android SDK 34+ (compileSdk 36), NDK 26+ (for `zeron-loro-android` via UniFFI)
- Rust 1.85+ with targets `aarch64-linux-android`, `x86_64-linux-android`
- Gradle wrapper (`./gradlew`)

No secrets in repo; no absolute local paths.

## Commands (wrapper only)

```sh
cd apps/android
gradle :app:assembleRelease       # arm64-only APK — what CI publishes
gradle :app:testDebugUnitTest     # unit tests (no credentials, no network)
gradle lint                       # static analysis
gradle :app:connectedDebugAndroidTest  # instrumented + native smoke (x86_64 emulator, local only)
```

Build the native lib first (needs NDK + Rust android targets):

```sh
cargo ndk -t arm64-v8a -o apps/android/app/src/main/jniLibs build --release -p zeron-loro-android
```

## CI

`.github/workflows/android.yml` runs on push to `main` only (plus manual
`workflow_dispatch`): cross-compile the arm64 native lib, `assembleRelease`,
assert the APK carries `lib/arm64-v8a/libzeron_loro_android.so` and no x86, then
upload it as the `zeron-android-release-apk` artifact for manual testing.

Unit / lint / instrumented jobs are not part of this workflow — run them locally
when touching protocol, adapter, or JNI code.

## ABI policy

- Release APK: `arm64-v8a` only (asserted in CI).
- `x86_64` is compiled only for local emulator instrumentation, never packaged.
- `armeabi-v7a`/`x86` never packaged. Verify: `unzip -l app/build/outputs/apk/release/*.apk | grep lib/`.

## Signing

The release build currently uses the debug signing key so the CI artifact is
installable for manual testing. Before any public release, add a real
`signingConfig` (keystore + secrets) and drop the debug fallback.

## Native build

- Single entry point `NativeLoader.loadOnce()` (`System.loadLibrary("zeron_loro_android")`).
- `jniLibs/` is generated by `cargo ndk` and git-ignored — no checked-in binaries.
- Reproducible: `crates/zeron-loro-android` pinned to `loro = 1.13`.

## Edge

- Production edge: `https://edge.zeron.sh` (`EdgeConfig.PRODUCTION_EDGE`, same default as iOS `Endpoints.edgeURL`).
- Sign-in: one **Log in to Zeron** button opens WorkOS AuthKit
  (`https://api.workos.com/user_management/authorize`) in a Custom Tab and returns
  through `zeron://callback` — the same authorization-code flow as iOS
  `SignInView`. The app validates `state`, then `POST /auth/exchange`,
  `GET /auth/orgs`, and `POST /auth/refresh` to scope the picked org.
- `GET /auth/signin` is not a browsable page; the edge only exposes
  `/auth/exchange`, `/auth/refresh`, `/auth/orgs`, `/auth/cli/callback`.
- Dev mode (`AUTH_MODE=dev` edge, bearer `user@org`) exists in `AuthStateMachine.signInDev` for debug/test only; it is not the default and never ships in release.
